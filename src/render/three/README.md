# `src/render/three/` — 3D adapter

Read-only 3D view over the same `Project` slice the SVG canvas consumes
(`src/store/plannerStore.ts`). It introduces no domain fields of its own.

## Coordinate mapping

World coordinates are mm with y pointing "south" on the plan. The scene
is metres, Y-up:

- `(x, y) mm` → `(x·0.001, 0, y·0.001)` (see `MM` in `ThreeCanvas.tsx`)
- 2D rotation θ (clockwise on screen) → `rotation.y = -θ`
- Model origin: centre in X/Z, floor at Y = 0

## Mapping

| Domain                       | Three.js                                              |
|------------------------------|-------------------------------------------------------|
| `RoomPolygon.corners`        | `Shape` → `ExtrudeGeometry` floor slab (`Floor.tsx`)  |
| Wall segments                | `BoxGeometry(length, wallHeight, wallThickness)`      |
| `Pillar.size` + position     | `BoxGeometry(width, height, depth)` mesh              |
| `InventoryItem.assetRef`     | GLB via `assetCatalog.glbUrl` (`InventoryMeshes.tsx`) |
| No `assetRef` / loading      | `BoxGeometry` in the item's stored size               |
| Camera                       | `OrbitControls` (`controls/OrbitView.tsx`)            |

## Assets

Catalog models under `public/assets/3d/*.glb` are generated by
`scripts/generate-assets.mjs` — parametric approximations built from the
SIS catalog dimensions. Regenerate with `node scripts/generate-assets.mjs`.
To upgrade any item to real CAD, export glTF/GLB from SolidWorks and
replace the file; the loader doesn't care where the GLB came from.
The three `.step` files alongside are the original CAD sources we have
so far (see `stepUrl` in `src/lib/assetCatalog.ts`).
